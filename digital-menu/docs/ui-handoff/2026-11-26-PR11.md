## UI 담당이 할 일
1. **[필수] 메뉴판 화면 · `index.html` · 빈 화면은 매장 이름만 (M-6)**
   `screens`에 그 번호가 없을 때, `type`을 모를 때, 격자 화면에 사진 있는 메뉴가 없을 때, 목록 화면에 메뉴가 없을 때 손님 앞에 설정 안내 글("N번 화면이 설정되지 않았습니다", "보일 메뉴가 없습니다", "알 수 없는 화면 종류")을 **띄우지 않는다**. 배경·브랜드 색 위에 `board.store.name`만 크게 가운데에. 위쪽 매장 제목 줄은 겹치지 않게 숨긴다.
   완료 기준: `/?screen=9`(없는 번호), 빈 구역만 넣은 격자 화면에서 1920×1080, 3840×2160, 세로 1080×1920, zoom 100·150 모두 매장 이름만 보이고 안내 글이 없다.
2. **[필수] 메뉴 관리 · `admin.html` · 가격 칸 (M-1, M-2)**
   가격 칸은 `type="text" inputmode="numeric"`으로 받고 "4,500", "4500원", "₩4,500"에서 숫자만 골라 낸다. 칸 옆에 "4,500원"처럼 쉼표 붙은 값을 바로 보여 준다. 저장 전에 한 번 더 묻는다: 예전 가격의 3배 이상이거나 3분의 1 이하, 0원, 100원 단위가 아님. 가격이 비면 "가격을 넣어 주세요.", 이름이 비면 "메뉴 이름을 넣어 주세요."
   완료 기준: 폰에서 숫자 자판이 뜨고, "4500원"을 넣으면 4500으로 저장되며, 4,500 → 45,000은 확인 창이 뜬다.
3. **[필수] 메뉴·가게 배경·홍보 이미지 · `admin.html` · 사진 줄이기 (M-8)**
   사진을 고르는 즉시 긴 변 1920px, JPEG 품질 0.85로 줄이고(이미 1MB 이하·1920px 이하 JPEG면 그대로), 폰 사진의 회전 정보(EXIF)를 반영하고, 투명 PNG는 흰 바탕. 작은 미리보기와 "새 사진: 8.2MB → 0.6MB로 줄임"을 보여 준다. 못 열면 "이 사진을 열 수 없습니다. 아이폰 사진(HEIC)은 설정 > 카메라 > 포맷에서 '높은 호환성'으로 바꾸거나, JPEG·PNG 사진으로 올려 주세요." 줄인 뒤 25MB가 넘으면 막는다. 줄인 파일을 `photoFile`/`backgroundFile`/`imageFile`에 넣는다.
   완료 기준: 4K 폰 사진(5MB 이상)이 2MB 이하로 올라가고, 세로로 찍은 사진이 눕지 않는다.
4. **[필수] 모든 저장·삭제·호출 버튼 · `admin.html` · 저장 중 잠금 (M-7)**
   저장 함수가 도는 동안 화면의 버튼·체크·파일·선택 칸을 모두 잠그고, 누른 버튼 글자를 "저장 중…"(지우기는 "지우는 중…", 호출은 "부르는 중…")으로 바꾼다. 끝나면 풀고 메뉴판을 다시 읽는다. 품절 체크가 실패하면 체크를 되돌린다.
   완료 기준: "추가"를 빠르게 두 번 눌러도 메뉴가 하나만 생긴다.
5. **[필수] 구역 · `admin.html` · 메뉴가 있는 구역 지우기 막기 (M-4)**
   그 구역에 메뉴가 있으면 확인 창 없이 "메뉴 N개가 있습니다. 메뉴를 다른 구역으로 옮기거나 지운 뒤 구역을 지워 주세요."를 보여 주고 지우지 않는다. 서버도 이 경우 `deleteSection`을 상태 400, 같은 뜻의 한글 문구로 거절하므로 그 `err.message`도 그대로 보여 준다. 메뉴 없는 구역의 확인 창은 "\"커피\" 구역을 지울까요?"(예전 "그 안의 메뉴를 모두" 문구는 빼기). 구역마다 "TV 화면 1·2번" 또는 "TV에 안 나옴" 표시.
   완료 기준: 메뉴가 있는 구역의 삭제를 눌러도 아무것도 지워지지 않는다.
6. **[필수] 홈(또는 메뉴 관리 맨 위) · `admin.html` · "지금 품절" 목록 (M-3)**
   `items` 중 `soldOut: true`인 것을 "지금 품절 N개: 아메리카노, 라떼"로 보여 주고, 메뉴마다 "품절 풀기" 버튼(`setSoldOut(storeId, id, false)`). 없으면 "품절인 메뉴가 없습니다."
   완료 기준: 로그인 직후 첫 화면에서 스크롤 없이 품절 개수가 보인다(POS 가로 화면).
7. **[필수] 메뉴 관리·화면 구성 · `admin.html` · TV에 어디 나오는지 알려 주기 (M-5, M-6)**
   메뉴를 저장한 뒤 "이 메뉴는 TV 1·2번 화면에 나옵니다." / 어느 화면에도 없는 구역이면 "이 구역은 어느 화면에도 없어 TV에 나오지 않습니다. 화면 구성에서 구역을 넣어 주세요." / 사진 격자 화면에만 있는데 사진이 없으면 "사진이 없어 TV에 나오지 않습니다…". 화면 구성에서는 `listDevices`로 화면마다 "띄운 TV: 입구 TV" 또는 "띄운 TV 없음"을 보여 주고, 원래 있던 화면 번호를 빼고 저장하면 "2번 화면을 지우면 이 화면을 띄운 TV(입구 TV)에는 메뉴 대신 매장 이름만 나옵니다. 지울까요?"로 묻는다. `listDevices`가 실패하면 TV 이름 없이 일반 문구로. 같은 화면 번호가 두 번이면 저장하지 않고 "N번 화면이 두 번 있습니다."
   완료 기준: TV가 띄운 화면을 지우려 하면 그 TV 이름이 확인 창에 나온다.
8. **[필수] 화면 구성 · `admin.html` · TV 미리보기 (M-9, 수정 화면 6번 "미리보기 후 저장")**
   화면마다 "미리보기" 버튼. 메뉴판 주소 `./?screen=N`을 iframe에 1920×1080(세로 보기면 1080×1920)으로 그린 뒤 `transform: scale()`로 화면에 맞게 줄인다. "세로로 보기/가로로 보기", "새 창으로 열기", "닫기". 저장된 모습이라는 안내("고친 뒤 저장해야 바뀐 모습이 보입니다"). 메뉴 이름이 20자를 넘으면 저장 뒤 "이름이 20자를 넘어 TV에서 작게 나올 수 있습니다."
   완료 기준: 폰(390px 너비)과 POS 가로 화면에서 미리보기가 잘리지 않고 TV 비율 그대로 보인다.
9. **[필수] 로그인 · `admin.html` · 비밀번호 잊음 안내 (M-10)**
   로그인 칸 아래 "비밀번호를 잊었으면 POS기에서 http://127.0.0.1:8090/reset.html 을 열어 다시 정하세요." (주소는 링크). 그 화면(`reset.html`)은 개발팀 것이라 만들거나 고치지 않는다.
   완료 기준: 로그인 화면에 안내가 보인다.

## 바뀐 계약
getBoard 데이터 모양은 바뀌지 않았다. api.js 함수가 하나 늘고, 두 함수의 실패 경우가 늘었다.

새 함수:
```
listDevices(storeId) → Promise<[{ id: string, name: string, screen: number | null }]>
```
```json
[ { "id": "d1", "name": "입구 TV", "screen": 1 }, { "id": "d2", "name": "계산대 위", "screen": null } ]
```

새 실패:
- `deleteSection(storeId, sectionId)` — 그 구역에 메뉴가 있으면 `err.status === 400`, `err.message`는 "이 구역에 메뉴 2개가 있습니다. 메뉴를 다른 구역으로 옮기거나 지운 뒤 구역을 지워 주세요." (바뀌기 전: 구역과 메뉴가 함께 지워짐)
- `login(email, password)` — 같은 주소에서 1분에 20번 넘게 부르면 `err.status === 429`.

화면에 보이는 데이터 변화: `calls`의 번호는 부른 지 10분이 지나면 서버가 지운다(바뀌기 전: 최근 30개를 직원이 지울 때까지).

## AI에 붙여 넣을 작업 지시
```
너는 디지털 메뉴판의 화면(UI) 담당을 돕는다. 이번 작업은 개발팀이 시안 화면에 넣은 "사장님 실수 막기" 기능(가격 확인, 사진 줄이기, 저장 중 잠금, 구역 지우기 막기, 품절 목록, TV에 어디 나오는지 안내, TV 미리보기, 비밀번호 잊음 안내)과 "빈 화면은 매장 이름만" 동작을 내 정식 화면(index.html, admin.html)에 옮기는 것이다.

# 배경
- 메뉴판 화면(index.html)은 안드로이드 보드(안드로이드 11~14)의 WebView가 35~66인치 TV에 띄운다. 보여 주기만 하고 주문 기능은 없다.
- 수정 화면(admin.html)은 매장 POS의 큰 가로 터치 화면과 폰 브라우저에서 연다.
- HTML, CSS, 자바스크립트만 쓴다. 프레임워크, 빌드 도구, import/export 모듈은 쓰지 않는다.

# 이번에 할 일 (필수)
1. index.html — 화면 번호가 screens에 없을 때, type을 모를 때, 격자 화면에 사진 있는 메뉴가 없을 때, 목록 화면에 메뉴가 없을 때 손님 앞에 설정 안내 글("N번 화면이 설정되지 않았습니다", "보일 메뉴가 없습니다", "알 수 없는 화면 종류")을 띄우지 않는다. 배경 이미지·브랜드 색 위에 board.store.name만 크게 가운데에 띄우고, 위쪽 매장 제목 줄은 숨긴다.
   완료 기준: /?screen=9(없는 번호), 빈 구역만 넣은 격자 화면이 1920×1080, 3840×2160, 세로 1080×1920, zoom 100·150 모두에서 매장 이름만 보인다.
2. admin.html 메뉴 관리 — 가격 칸은 type="text" inputmode="numeric". "4,500", "4500원", "₩4,500"에서 숫자만 골라 쓴다(숫자가 없으면 빈 값). 칸 옆에 "4,500원"처럼 쉼표 붙은 값을 입력하는 대로 보여 준다. 저장 전에 confirm으로 한 번 더 묻는다: 예전 가격의 3배 이상이거나 3분의 1 이하("4,500원 → 45,000원, 맞나요?"), 0원("가격이 0원입니다. 이대로 저장할까요?"), 100원 단위가 아님("4,550원은 100원 단위가 아닙니다. 이대로 저장할까요?"). 이름이 비면 "메뉴 이름을 넣어 주세요.", 첫 가격이 비면 "가격을 넣어 주세요."
   완료 기준: 폰에서 숫자 자판이 뜨고 "4500원"이 4500으로 저장되며, 4,500 → 45,000은 확인 창이 뜬다.
3. admin.html 사진 칸(메뉴 사진, 가게 배경, 홍보 이미지 모두) — 고르는 즉시 긴 변 1920px, JPEG 품질 0.85로 줄인다. 이미 JPEG이고 긴 변 1920px 이하, 1MB 이하면 그대로 둔다. createImageBitmap(file, { imageOrientation: 'from-image' })로 폰 사진의 회전을 반영하고, 안 되면 img 요소로 연다. 투명 PNG는 흰 바탕을 깐다. canvas.toBlob으로 만든 JPEG를 File로 바꿔 photoFile/backgroundFile/imageFile에 넣는다. 작은 미리보기 사진과 "새 사진: 8.2MB → 0.6MB로 줄임"을 보여 준다. 못 열면 "이 사진을 열 수 없습니다. 아이폰 사진(HEIC)은 설정 > 카메라 > 포맷에서 '높은 호환성'으로 바꾸거나, JPEG·PNG 사진으로 올려 주세요." 줄인 뒤에도 25MB가 넘으면 "사진이 25MB를 넘습니다. 더 작은 사진으로 올려 주세요."
   완료 기준: 4K 폰 사진(5MB 이상)이 2MB 이하로 올라가고, 세로로 찍은 사진이 눕지 않는다.
4. admin.html 모든 저장·삭제·호출·품절 — 함수가 도는 동안 화면의 버튼, 체크, 파일 칸, 선택 칸을 모두 잠그고(disabled) 누른 버튼 글자를 "저장 중…"(지우기 "지우는 중…", 번호 호출 "부르는 중…")으로 바꾼다. 끝나면 풀고 getBoard로 다시 읽어 그린다. 품절 체크가 실패하면 체크를 원래대로 되돌린다.
   완료 기준: "추가"를 빠르게 두 번 눌러도 메뉴가 하나만 생긴다.
5. admin.html 구역 — 그 구역(sectionId)에 메뉴가 하나라도 있으면 지우지 않고 "메뉴 N개가 있습니다. 메뉴를 다른 구역으로 옮기거나 지운 뒤 구역을 지워 주세요."를 보여 준다. 메뉴가 없으면 confirm("\"커피\" 구역을 지울까요?") 뒤 deleteSection. 서버도 메뉴 있는 구역은 상태 400으로 거절하므로 err.message를 그대로 보여 준다. 구역마다 "TV 화면 1·2번"(그 구역을 sectionIds에 넣은 grid·list 화면 번호) 또는 "TV에 안 나옴" 표를 붙인다.
   완료 기준: 메뉴가 있는 구역의 삭제를 눌러도 아무것도 지워지지 않는다.
6. admin.html 홈(첫 화면) 맨 위 — "지금 품절 N개: 아메리카노, 라떼"와 메뉴마다 "품절 풀기" 버튼(setSoldOut(storeId, itemId, false)). 없으면 "품절인 메뉴가 없습니다."
   완료 기준: POS 가로 화면에서 로그인 직후 스크롤 없이 품절 개수가 보인다.
7. admin.html TV 안내 —
   a. 메뉴를 저장한 뒤: 그 구역을 넣은 grid·list 화면이 없으면 "이 구역은 어느 화면에도 없어 TV에 나오지 않습니다. 화면 구성에서 구역을 넣어 주세요." 사진 없는 메뉴가 grid 화면에만 있으면 "사진이 없어 TV에 나오지 않습니다. N번은 사진 격자 화면이라 사진 있는 메뉴만 나옵니다. 사진을 넣어 주세요." 그 밖에는 "이 메뉴는 TV 1·2번 화면에 나옵니다."(사진이 없어 빠지는 grid 화면이 있으면 괄호로 덧붙임). 메뉴 이름이 20자를 넘으면 "이름이 20자를 넘어 TV에서 작게 나올 수 있습니다."를 덧붙인다.
   b. 화면 구성: listDevices(storeId)로 TV 목록을 읽어 화면마다 "띄운 TV: 입구 TV" 또는 "띄운 TV 없음"을 보여 준다. listDevices가 실패하면 TV 이름 없이 넘어간다.
   c. 저장할 때 같은 화면 번호가 두 번이면 저장하지 않고 "N번 화면이 두 번 있습니다. 번호를 바꿔 주세요." 원래 있던 화면 번호가 빠졌으면 confirm: "2번 화면을 지우면 이 화면을 띄운 TV(입구 TV)에는 메뉴 대신 매장 이름만 나옵니다. 지울까요?"(띄운 TV가 없으면 "2번 화면을 지웁니다. 지금 이 화면을 띄운 TV는 없습니다.", TV 목록을 못 읽었으면 "2번 화면을 지우면 그 화면을 띄운 TV에는 메뉴 대신 매장 이름만 나옵니다.")
   완료 기준: TV가 띄운 화면을 빼고 저장하면 그 TV 이름이 확인 창에 나온다.
8. admin.html 미리보기 — 화면 구성의 화면마다 "미리보기" 버튼. 메뉴판 주소 ./?screen=N 을 iframe으로 1920×1080(세로 보기면 1080×1920) 크기로 그리고 transform: scale(배율), transform-origin: 0 0 으로 지금 창에 맞게 줄인다(창 크기가 바뀌면 다시 맞춘다). "세로로 보기/가로로 보기", "새 창으로 열기", "닫기"와 "저장된 화면입니다. 고친 뒤 저장해야 바뀐 모습이 보입니다." 안내.
   완료 기준: 폰(390px 너비)과 POS 가로 화면에서 미리보기가 잘리지 않고 TV 비율 그대로 보인다.
9. admin.html 로그인 — 로그인 칸 아래 "비밀번호를 잊었으면 POS기에서 http://127.0.0.1:8090/reset.html 을 열어 다시 정하세요."(주소는 링크). reset.html은 다른 담당자가 만든 화면이라 만들거나 고치지 않는다.

# 하면 좋은 것 (권장)
- index.html: 서버와 1분 넘게 끊기거나 부른 지 10분이 지나면 calls가 빈 배열로 온다. 번호 띠와 번호 전용 화면이 빈 상태로 자연스럽게 바뀌고(번호 전용 화면은 매장 이름과 안내), 비었다고 깜빡이지 않게 한다.

- admin.html 전체: 누르는 칸은 최소 2.75rem, 폭 600px 이하에서 줄이 아래로 접히고 가로 스크롤이 없게. 안내 글 줄은 위에 붙어 있고 줄바꿈을 보여 준다(white-space: pre-line).
- admin.html은 오래된 폰 브라우저에서도 열리게 var, function, appendChild 정도만 쓴다(async/await, 화살표 함수, replaceChildren 없이).

# 계약 2: 화면이 부르는 api.js 함수 (모두 Promise를 돌려준다)
- 부르는 방식: 화면에서 <script src="api.js"></script>로 불러오면 전역 객체 api가 생긴다.
  api.getBoard(storeId).then(function (board) { ... }) 처럼 부른다. import/export(모듈)는 쓰지 않는다.
- 실패하면 Promise가 Error로 거절된다. err.message에 사유, err.status에 상태 코드가 있다.
  사유는 아직 서버의 영어 문장이 섞여 온다. 지금은 그대로 보여 주고, 한글로 바꾸는 일은 다른 담당자가 한다.
- 인자와 돌려받는 값의 모양은 getBoard가 돌려주는 모양 그대로다. 수정할 때는 id를 넣고, 새로 만들 때는 id를 뺀다.
- getBoard(storeId) : 메뉴판 전체 (위 데이터 모양). TV 화면과 수정 화면이 같이 쓴다.
  items는 구역 구분 없이 order 순서로 온다. 화면에서 sectionId로 묶는다. 사진이 없으면 photoUrl은 null
- login(email, password) : { kind, storeId }를 돌려줌. kind는 hq·franchise·independent 중 하나.
  로그인은 이 기기(브라우저)에 저장되어 아래 저장 함수들이 쓴다.
  [이번 변경] 같은 주소에서 1분에 20번 넘게 부르면 err.status 429로 실패한다.
- session() : 이 기기에 저장된 로그인 { kind, storeId } 또는 null. 수정 화면을 열 때 로그인 화면을 건너뛸지 정한다.
- logout() : 이 기기의 로그인을 지운다.
- saveItem(storeId, item) : 메뉴 추가·수정. 저장한 메뉴의 id를 돌려준다.
  새 사진은 item.photoFile에 파일(input type=file의 File)로 담고, 사진을 지우려면 item.photoUrl을 null로 둔다.
  POS 상품 코드는 item.posCode(지우려면 null, 넘기지 않으면 그대로).
- deleteItem(storeId, itemId) : 메뉴 삭제
- saveSection(storeId, section) : 구역 추가·수정. 저장한 구역의 id를 돌려준다.
- deleteSection(storeId, sectionId) : 구역 삭제.
  [이번 변경] 그 구역에 메뉴가 있으면 서버가 지우지 않고 err.status 400, err.message "이 구역에 메뉴 N개가 있습니다. 메뉴를 다른 구역으로 옮기거나 지운 뒤 구역을 지워 주세요."로 거절한다. 메뉴가 함께 지워지는 일은 없다.
- setSoldOut(storeId, itemId, soldOut) : 품절 켜고 끄기
- saveScreens(storeId, screens) : TV 화면 구성 전체 저장. 화면 번호(no)로 맞춰 고치고, 빠진 번호는 지운다.
  홍보 이미지는 screen.imageFile에 파일로 담고, 지우려면 screen.imageUrl을 null로 둔다. 문구는 앞 두 줄만 저장된다.
- saveStore(storeId, store) : 가게 이름, 브랜드 색. 배경 이미지는 store.backgroundFile에 파일로 담고,
  지우려면 store.backgroundUrl을 null로 둔다.
- 사진 파일은 한 장에 25MB까지 받는다.
- callNumber(storeId, number) : 번호(1~9999)를 부른다. 이미 부른 번호면 맨 앞으로 옮긴다.
  가맹점 계정도 부를 수 있다. 매장마다 최근 30개만 남고 나머지는 서버가 지운다.
- clearCalls(storeId, number) : 부른 번호 하나를 지운다. number를 빼면 그 매장 번호를 모두 지운다.
- listDevices(storeId) : 이 매장에 붙은 TV 목록 [{ id, name, screen }]. screen은 그 TV가 띄운 화면 번호(모르면 null).
  로그인한 매장 계정만 읽을 수 있다. 수정 화면이 "이 화면을 띄운 TV"를 알려 주는 데 쓴다(못 읽으면 일반 문구로).
  예: [ { "id": "d1", "name": "입구 TV", "screen": 1 }, { "id": "d2", "name": "계산대 위", "screen": null } ]
- onBoardChange(callback) : 메뉴판 화면의 바로 반영용. board.js가 부르므로 화면에서는 부르지 않는다.

# 지켜야 할 규칙
- 데이터를 읽고 저장하는 곳은 api.js 함수로만 부른다. 화면 코드에서 서버를 직접 부르지 않는다(fetch 금지). 미리보기 iframe으로 ./?screen=N 을 여는 것은 괜찮다.
- api.js와 board.js는 다른 담당자가 만든 파일이다. 고치지 않는다.
- 메뉴판 화면(index.html)은 전역 함수 renderBoard(board, screenNo) 하나만 정의한다. board는 계약 1의 데이터, screenNo는 이 TV가 띄울 화면 번호(숫자). 같은 함수가 여러 번 불리므로 불릴 때마다 화면을 비우고 처음부터 다시 그린다. index.html 맨 아래에는 화면 스크립트 다음에 <script src="api.js"></script>, <script src="board.js"></script>를 이 순서로 둔다. 화면에서 getBoard를 직접 부르지 않는다.
- 메뉴판 크기는 px로 고정하지 말고 vmax·rem으로 잡고, 글자 크기에 var(--zoom, 1)을 곱한다. 예: html{font-size:calc(1.5vmax * var(--zoom, 1))}
- 가로·세로 배치는 @media (orientation: portrait)로 나눈다.
- 메뉴 이름, 매장 이름처럼 사람이 입력한 글은 innerHTML이 아니라 textContent로 넣는다.
- 메뉴판은 스크롤과 마우스 커서가 없다. 1920×1080, 3840×2160, 세로 1080×1920에서, zoom 100과 150에서 모두 잘림 없이 확인한다(브라우저 개발자 도구의 기기 크기 설정, 주소 끝에 &zoom=150).
- 수정 화면은 POS 큰 가로 터치 화면과 폰 좁은 화면 모두에서 쓸 수 있어야 한다.
```
