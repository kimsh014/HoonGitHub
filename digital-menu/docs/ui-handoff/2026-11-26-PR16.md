## UI 담당이 할 일
1. **[필수] 메뉴판 화면 · `index.html` · 같은 번호를 다시 불러도 깜빡이기**
   지금까지는 "이전에 그린 첫 번호(`calls[0]`)와 다를 때만" 깜빡였다. 이제는 `calls[0]`과 `lastCallAt`을 **둘 다** 기억해 두고, 둘 중 하나라도 바뀌면 새 번호로 보고 번호 띠·번호 전용 화면의 맨 앞 번호를 깜빡인다. 가격 수정처럼 다른 이유로 `renderBoard`가 다시 불릴 때(두 값 그대로)는 깜빡이지 않는다. 처음 그릴 때와 `calls`가 빈 배열일 때도 깜빡이지 않는다. 시안의 예: `var first = calls.length ? calls[0] + '@' + (board.lastCallAt || '') : null`.
   완료 기준: 가짜 데이터에서 ① `calls: [12]`, `lastCallAt: 1000` → ② 같은 값으로 다시 `renderBoard` → ③ `calls: [12]`, `lastCallAt: 5000`으로 다시. ②에서는 안 깜빡이고 ③에서 깜빡인다. 번호 띠(callBand가 켜진 grid·list·promo)와 번호 전용 화면 모두, 1920×1080, 3840×2160, 세로 1080×1920, zoom 100·150에서.
2. **[필수] 수정 화면 "POS·키오스크 연동" · `admin.html` · 새 키 안내 문구**
   새 연동 키 만들기 확인 창: "새 키를 만들면 예전 키를 쓰던 POS·키오스크와 POS기의 번호 호출 키패드가 모두 끊깁니다.\n새 키를 그 기기들에 다시 넣어야 합니다. 만들까요?" 키를 만든 뒤 안내: "연동 키를 만들었습니다. 지금 복사해 POS·키오스크와 번호 호출 키패드 설정에 넣어 주세요."
   완료 기준: 정식 수정 화면에서 새 키를 누르면 위 두 문구가 그대로 보인다(확인 창은 두 줄).

- **[권장] 수정 화면 "번호 호출" · `admin.html` · 키패드로 부른 번호도 보이게**
  이제 직원이 POS기 키패드로 번호를 부르고 빼므로, 수정 화면의 부른 번호 목록이 금방 낡는다. 번호 호출 화면이 열려 있는 동안 `getBoard`를 몇 초(예: 5초)마다 다시 읽어 번호 목록만 새로 그리거나, 최소한 "새로 고침" 버튼을 둔다. 입력 중인 번호 칸은 지우지 않는다. 목록 위에 "키패드로 부른 번호도 여기 나옵니다. 부른 번호는 10분 뒤 TV에서 저절로 빠집니다." 안내.
  완료 기준: 다른 창(또는 가짜 데이터)에서 번호를 더하면 5초 안에 수정 화면 목록에 나타나고, 치던 번호는 그대로 남는다.
- **[권장] 수정 화면 "번호 호출" · `admin.html` · 다시 부르기와 잘못 부르기 확인 (점검표 M-26)**
  키패드 앱과 같은 기준으로 맞춘다. ① 부른 번호마다 "다시" 버튼: `callNumber(storeId, n)`을 다시 부르면 그 번호가 맨 앞으로 가고 `lastCallAt`이 바뀌어 TV가 다시 깜빡인다. ② 넣은 번호가 이미 목록에 있으면 "12번은 이미 TV에 있습니다. 다시 부를까요?", 맨 앞 번호와 30 넘게 떨어졌으면 "101번 다음에 201번이 맞나요?"를 confirm으로 한 번 더 묻는다.
  완료 기준: 목록의 "다시"를 누르면 그 번호가 맨 앞으로 오고 메뉴판 화면이 깜빡인다. 먼 번호를 치면 확인 창이 뜬다.
- **[참고]** 키패드 앱(`order-app/`)은 Windows 프로그램이고 UI 담당 작업 범위가 아니다. 키패드가 쓰는 서버 경로(`/api/menuboard/pos/calls`, 연동 키)도 수정 화면에서 부르지 않는다. 수정 화면의 번호 호출은 예전처럼 `callNumber`·`clearCalls`만 쓴다.
- **[참고]** `board.js`가 서버와 1분 넘게 끊기면 `calls: []`로 다시 부르는 동작(PR #11)은 그대로다. 다시 연결되어 같은 번호가 돌아오면 한 번 깜빡일 수 있는데, 시안도 같다. 고칠 필요 없다.

## 바뀐 계약
getBoard 데이터에 필드가 하나 늘었다. api.js 함수 이름·인자·돌려주는 값은 그대로다.

바뀌기 전:
```json
{ "...": "...", "calls": [107, 106, 105] }
```

바뀐 뒤:
```json
{ "...": "...", "calls": [107, 106, 105], "lastCallAt": 1795651200000 }
```
- `lastCallAt`: `calls` 맨 앞 번호를 부른 시각(밀리초). 번호가 없으면 `null`.
- 직원이 같은 번호를 '다시 부르기'하면 `calls`는 그대로이고 이 값만 바뀐다. 화면은 맨 앞 번호나 이 값이 바뀌면 새 번호로 보고 강조(깜빡임)한다.
- 수정 화면에서 `callNumber(storeId, n)`으로 이미 있는 번호를 다시 불러도 이 값이 바뀐다.

## AI에 붙여 넣을 작업 지시
```
너는 디지털 메뉴판의 화면(UI) 담당을 돕는다. 이번 작업은 메뉴판 데이터에 새로 생긴 lastCallAt(맨 앞 번호를 부른 시각)을 써서 "같은 번호를 다시 불러도 TV가 깜빡이게" 하고, 수정 화면의 연동 키 안내 문구와 번호 호출 화면을 POS기 번호 키패드가 생긴 상황에 맞추는 것이다.

# 배경
- 메뉴판 화면(index.html)은 안드로이드 보드(안드로이드 11~14)의 WebView가 35~66인치 TV에 띄운다. 보여 주기만 하고 주문 기능은 없다. 수정 화면(admin.html)은 매장 POS의 큰 가로 터치 화면과 폰 브라우저에서 연다.
- HTML, CSS, 자바스크립트만 쓴다. 프레임워크, 빌드 도구, import/export 모듈은 쓰지 않는다.
- 새로 생긴 일: 음식이 나오면 직원이 POS기의 USB 숫자 키패드로 번호+Enter를 쳐서 TV에 번호를 띄운다(다른 담당자가 만든 별도 Windows 앱). 그래서 번호는 수정 화면 말고도 키패드에서 들어오고 빠진다. 키패드 앱은 만들지 않는다.

# 이번에 할 일 (필수)
1. index.html — 새 번호 깜빡임 판단을 바꾼다. 지금까지는 이전에 그린 첫 번호(calls[0])와 다를 때만 깜빡였다. 이제는 calls[0]과 lastCallAt을 둘 다 기억해 두고, 둘 중 하나라도 바뀌면 번호 띠와 번호 전용 화면의 맨 앞 번호를 깜빡인다. 예: var first = calls.length ? calls[0] + '@' + (board.lastCallAt || '') : null 을 이전 값과 비교. 처음 그릴 때, calls가 빈 배열일 때, 다른 이유(가격 수정 등)로 두 값이 그대로인 채 renderBoard가 다시 불릴 때는 깜빡이지 않는다.
   완료 기준: 가짜 데이터로 ① calls [12], lastCallAt 1000 → ② 같은 값으로 다시 renderBoard → ③ calls [12], lastCallAt 5000. ②에서 안 깜빡이고 ③에서 깜빡인다. 번호 띠(callBand가 켜진 grid·list·promo 화면)와 번호 전용 화면(type "calls") 모두, 1920×1080, 3840×2160, 세로 1080×1920, zoom 100·150에서.
2. admin.html "POS·키오스크 연동" — 새 연동 키 만들기 확인 창(confirm) 문구를 "새 키를 만들면 예전 키를 쓰던 POS·키오스크와 POS기의 번호 호출 키패드가 모두 끊깁니다.\n새 키를 그 기기들에 다시 넣어야 합니다. 만들까요?"로, 키를 만든 뒤 안내를 "연동 키를 만들었습니다. 지금 복사해 POS·키오스크와 번호 호출 키패드 설정에 넣어 주세요."로 바꾼다.
   완료 기준: 새 키를 누르면 위 두 문구가 그대로 보인다(확인 창은 두 줄).

# 하면 좋은 것 (권장)
3. admin.html 번호 호출 화면 — 번호 호출 화면이 열려 있는 동안 getBoard를 5초마다 다시 읽어 부른 번호 목록만 새로 그린다(또는 "새로 고침" 버튼). 입력 중인 번호 칸은 지우지 않는다. 목록 위에 "키패드로 부른 번호도 여기 나옵니다. 부른 번호는 10분 뒤 TV에서 저절로 빠집니다." 안내.

   완료 기준: "다시"를 누르면 그 번호가 맨 앞으로 오고 메뉴판이 깜빡인다. 먼 번호를 치면 확인 창이 뜬다.

- callBand가 true인 화면(grid·list·promo)은 아래쪽에 번호 띠를 붙인다. calls 화면에는 callBand가 없다.

# 계약 2: 이번에 쓰는 api.js 함수 (모두 Promise를 돌려준다, 이번에 바뀌지 않음)
- 부르는 방식: 화면에서 <script src="api.js"></script>로 불러오면 전역 객체 api가 생긴다.
  api.getBoard(storeId).then(function (board) { ... }) 처럼 부른다. import/export(모듈)는 쓰지 않는다.
- 실패하면 Promise가 Error로 거절된다. err.message에 사유, err.status에 상태 코드가 있다.
- getBoard(storeId) : 메뉴판 전체 (위 데이터 모양). TV 화면과 수정 화면이 같이 쓴다.
- session() : 이 기기에 저장된 로그인 { kind, storeId } 또는 null.
- callNumber(storeId, number) : 번호(1~9999)를 부른다. 이미 부른 번호면 맨 앞으로 옮긴다(이때 lastCallAt도 바뀐다).
  가맹점 계정도 부를 수 있다. 매장마다 최근 30개만 남고 나머지는 서버가 지운다.
- clearCalls(storeId, number) : 부른 번호 하나를 지운다. number를 빼면 그 매장 번호를 모두 지운다.
- issuePosKey(storeId) : POS·키오스크 연동 키를 새로 만들어 문자열로 돌려준다. 예전 키는 바로 막힌다(키오스크·POS·번호 키패드 모두).
  키는 이때 한 번만 볼 수 있으니 화면에 띄워 복사하게 하고, 다시 만들기 전에 묻는다.
- onBoardChange(callback) : 메뉴판 화면의 바로 반영용. board.js가 부르므로 화면에서는 부르지 않는다.

# 지켜야 할 규칙
- 데이터를 읽고 저장하는 곳은 api.js 함수로만 부른다. 화면 코드에서 서버를 직접 부르지 않는다(fetch 금지).
- api.js와 board.js는 다른 담당자가 만든 파일이다. 고치지 않는다.
- 메뉴판 화면(index.html)은 전역 함수 renderBoard(board, screenNo) 하나만 정의한다. board는 계약 1의 데이터, screenNo는 이 TV가 띄울 화면 번호(숫자). 같은 함수가 여러 번 불리므로 불릴 때마다 화면을 비우고 처음부터 다시 그린다(깜빡임 판단용으로 이전 값을 전역 변수 하나에 기억하는 것은 괜찮다). index.html 맨 아래에는 화면 스크립트 다음에 <script src="api.js"></script>, <script src="board.js"></script>를 이 순서로 둔다. 화면에서 getBoard를 직접 부르지 않는다.
- 메뉴판 크기는 px로 고정하지 말고 vmax·rem으로 잡고, 글자 크기에 var(--zoom, 1)을 곱한다. 예: html{font-size:calc(1.5vmax * var(--zoom, 1))}
- 가로·세로 배치는 @media (orientation: portrait)로 나눈다.
- 메뉴 이름, 매장 이름처럼 사람이 입력한 글은 innerHTML이 아니라 textContent로 넣는다.
- 메뉴판은 스크롤과 마우스 커서가 없다. 1920×1080, 3840×2160, 세로 1080×1920에서, zoom 100과 150에서 모두 잘림 없이 확인한다(브라우저 개발자 도구의 기기 크기 설정, 주소 끝에 &zoom=150).
- 수정 화면은 POS 큰 가로 터치 화면과 폰 좁은 화면 모두에서 쓸 수 있어야 한다. 오래된 폰 브라우저를 위해 var, function, appendChild 정도만 쓴다.

# 서버 없이 작업할 때
같은 함수 이름으로 가짜 데이터를 돌려주는 api.js를 따로(예: fake/api.js) 만들어 쓰고, 진짜 api.js를 덮어쓰지 않는다. 예:
var BOARD = /* 위 계약 1 예시를 복사 */
window.api = {
  getBoard: function () { return Promise.resolve(JSON.parse(JSON.stringify(BOARD))) },
  session: function () { return { kind: 'independent', storeId: 'store1' } },
  callNumber: function (storeId, n) {
    BOARD.calls = [n].concat(BOARD.calls.filter(function (x) { return x !== n })).slice(0, 30)
    BOARD.lastCallAt = Date.now()                       // 같은 번호를 다시 불러도 바뀐다
    return new Promise(function (ok) { setTimeout(ok, 800) })
  },
  clearCalls: function (storeId, n) {
    BOARD.calls = n == null ? [] : BOARD.calls.filter(function (x) { return x !== n })
    if (!BOARD.calls.length) BOARD.lastCallAt = null
    return new Promise(function (ok) { setTimeout(ok, 800) })
  },
  issuePosKey: function () { return Promise.resolve('mbpos_가짜키') },
  onBoardChange: function () {}
}
// 키패드로 번호가 들어오는 상황 흉내: 개발자 도구 콘솔에서 api.callNumber('store1', 12) 를 직접 부른다.
메뉴판 깜빡임 확인은 콘솔에서 renderBoard(같은 board, 1)과, lastCallAt만 바꾼 board로 renderBoard를 번갈아 불러 본다.
```
