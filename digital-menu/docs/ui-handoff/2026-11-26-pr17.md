## 바뀐 계약
데이터(계약 1)와 api.js 함수(계약 2)는 바뀌지 않았습니다. 화면 규칙만 하나 늘었습니다.

바뀌기 전: index.html은 UI 담당이 통째로 바꾸는 시안, 색은 index.html 안에 직접 씀.

바뀐 뒤: index.html은 개발팀 배치 + "테마 값" 변수. 색·모양은 `themes/<이름>.css`가 `:root{ --변수: 값; }`만 바꿔 정함.
```
주소: /?screen=화면번호[&zoom=배율%][&theme=테마이름]
테마 파일: server/pb_public/themes/<이름>.css   (이름: 영어 소문자·숫자·-, 1~32자)
목록:      server/pb_public/themes/list.json   [{ "id", "name", "kind": "light"|"dark", "sampleStore", "sampleBrand": "#rrggbb", "desc" }]
```
제안 단계(아직 없음): getBoard의 `store`에 `"theme": "cafe"`(없으면 null). index.html은 이미 이 값이 오면 씁니다.

````
너는 디지털 메뉴판의 화면(UI) 담당을 돕는다. 이번 작업은 TV 메뉴판의 업종별 "테마 파일"(CSS 하나)을 만들고 다듬는 것이다. 화면 배치는 이미 다른 담당자(개발팀)가 만들어 두었고, 우리는 색과 모양만 정한다.

# 배경
- 안드로이드 보드의 WebView(안드로이드 11~14)에 뜨는 매장 천장 TV 메뉴판(35~66인치, 1920×1080~4K, 세로로도 건다)과, POS·폰 브라우저용 수정 화면이 있다.
- HTML·CSS·자바스크립트만 쓴다. 프레임워크·빌드 도구·모듈(import/export) 없음.
- 이 매장들은 번호 호출이 핵심이다(주문 → 번호표 → 준비되면 TV에 번호). 멀리서도 가장 최근 번호가 한눈에 보여야 한다.

# 화면 구조 (개발팀이 만든 index.html, 고치지 않는다)
- 화면 종류 네 가지: 사진 격자형(grid), 목록 + 큰 사진형(list), 홍보 화면(promo, 이미지 + 문구 두 줄), 번호 전용 화면(calls, 가장 최근 번호를 아주 크게, 번호가 없으면 매장 이름과 안내).
- 메뉴·홍보 화면 아래에는 "번호 띠"(준비된 번호 한 줄, 가장 최근 번호 강조)가 붙을 수 있다. 맨 위에는 매장 이름 띠, 구역마다 띠 모양 제목.
- 칸 수, 글자 크기(화면 긴 변에 비례, vmax·rem과 var(--zoom, 1)), 넘치면 줄이기, 4K·세로 대응(@media (orientation: portrait)), 품절 흐림, 새 번호 깜빡임은 index.html이 이미 한다. 스크롤·마우스 커서 없음.
- 색·모양은 모두 아래 "테마 값" CSS 변수로 쓰여 있다. 테마 파일은 이 변수 값만 바꾼다.
- 사장님이 고른 브랜드 색은 var(--brand), 그 위 글자색은 var(--on-brand)(화면이 흰색·검은색 중 잘 보이는 쪽을 자동으로 고름). 사장님은 아무 색이나 고를 수 있으니 빨강·노랑·남색 어느 것이어도 어울려야 한다.
- 주소: /?screen=화면번호&zoom=배율%&theme=테마이름 (예: ?screen=1&zoom=150&theme=chicken). 테마 파일이 없거나 이름이 틀리면 기본 모습으로 나온다.

# 테마 파일 규칙 (어기면 check_themes.js가 실패한다)
1. 파일 안에는 주석과 :root { --값: …; } 한 덩어리만. .card {…} 같은 다른 선택자, @import, @font-face, @media 금지.
2. 아래 "테마 값" 목록의 변수만 바꾼다. --brand, --on-brand, --zoom, --fit, --pad 는 바꾸지 않는다. 안 바꾼 값은 기본값을 쓴다.
3. 크기는 em·rem만(px 금지, 4K에서 반으로 작아진다). 글자 크기·여백·위치·칸 수는 테마 값에 없으므로 바꿀 수 없다.
4. url()은 themes/ 폴더 안의 그림 파일만(예: url(dots.png), 한 장 300KB 이하 권장). 바깥 인터넷 주소의 그림·글꼴 금지(매장 인터넷이 끊겨도 보여야 한다).
5. 글꼴: 보드에는 Noto Sans CJK만 있고 확실한 굵기는 400과 700뿐. 다른 글꼴이 필요하면 만들지 말고 "개발팀 요청"으로 알려 준다.
6. 글자색과 바탕색이 둘 다 #rrggbb 고정 색인 짝(--ink/--base, --ink/--panel, --top-ink/--top-bg, --title-ink/--title-bg, --band-ink/--band-bg, --call-ink/--call-bg, --sold-ink/--sold-bg, --badge-new-ink/--badge-new-bg, --badge-best-ink/--badge-best-bg)은 명도 대비 4.5 이상.
7. 밝은 바탕 테마면 --ink, --muted, --veil(매장 배경 사진 위 막), --band-*, --hot·--ice도 어두운 글에 맞게 함께 바꾼다.
8. 이름은 영어 소문자·숫자·- 만, 1~32자(주소에 들어간다). 파일 20KB 이하.

# 테마 값 (index.html에 있는 기본값 그대로 = 테마가 없을 때의 모습)
```css
  /* renderBoard가 넣는 값. 테마에서 바꾸지 않는다 */
  --brand:#c8102e;           /* 매장 브랜드 색 (사장님이 고름) */
  --on-brand:#fff;           /* 브랜드 색 위 글자: 흰색·검은색 중 잘 보이는 쪽 */

  /* ── 테마 값: themes/*.css는 이 블록의 변수만 바꾼다 (기본값 = 테마 없음) ── */

# 화면이 부르는 api.js 함수 (계약 2 중 이번에 관련된 것)
- 부르는 방식: <script src="api.js"></script>로 불러오면 전역 객체 api가 생긴다. 모든 함수는 Promise를 돌려준다.
- getBoard(storeId) : 메뉴판 전체 (위 데이터 모양). board.js가 부르고 index.html의 renderBoard(board, screenNo)에 넘긴다. 화면에서 직접 부르지 않는다.
- onBoardChange(callback) : 바로 반영용. board.js가 부르므로 화면에서는 부르지 않는다.
- saveStore(storeId, store) : 가게 이름, 브랜드 색. 배경 이미지는 store.backgroundFile에 파일로 담고, 지우려면 store.backgroundUrl을 null로 둔다. (브랜드 색을 바꿔 보며 테마를 확인할 때 수정 화면이 쓰는 함수)

# 지켜야 할 규칙 (전체 작업 공통)
- 데이터는 api.js 함수로만 읽고 쓴다. 화면 코드에서 서버를 직접 부르지 않는다.
- api.js, board.js 는 고치지 않는다. index.html 도 이번부터는 개발팀 파일이므로 고치지 않는다(전역 함수 renderBoard(board, screenNo) 하나로 화면을 그리는 구조는 그대로다).
- 크기는 vmax·rem과 var(--zoom, 1)에 비례하게, 가로·세로는 @media (orientation: portrait) 로 나눈다(이 부분은 index.html이 이미 한다. 테마는 em·rem만 쓴다).
- 사람이 입력한 글(메뉴 이름 등)은 innerHTML이 아니라 textContent로 넣는다.
- 확인 해상도: 1920×1080, 3840×2160, 세로 1080×1920, 각각 zoom 100과 150. 스크롤과 마우스 커서는 없다.

# 하지 말 것
- 계약(데이터 모양, api.js 함수 이름·인자, 테마 값 목록)을 임의로 바꾸기. 바꾸고 싶으면 "개발팀 요청"으로 정리해 나에게 준다.
- 배치(칸 수, 글자 크기, 위치, 요소 숨기기·더하기)를 바꾸려고 index.html이나 다른 선택자를 고치기. 필요하면 "개발팀 요청"으로.
- 서버 코드, 주문·장바구니 같은 범위 밖 기능.

# 일하는 방식
1. 작업 전에 화면 설계를 먼저 보여 주고 확인받은 뒤 코드를 써라. 이번 작업에서 화면 설계란: 색 견본표(바탕, 상자, 글, 보조 글, 매장 이름 띠, 구역 제목, 번호 띠, 가장 최근 번호, NEW·BEST 딱지, 품절 표, HOT/ICE)와 모서리·테두리·그림자 느낌의 한 줄 설명, 그리고 브랜드 색이 빨강·노랑·남색일 때 어떻게 보일지.
2. 확인되면 테마 파일 전체와 list.json 한 줄을 준다.
3. 내가 검사 결과나 스크린샷을 붙이면 그걸 보고 고친다. 대비가 모자라다는 실패가 나오면 바탕은 두고 글자색부터 바꾼다.
````
