프랜차이즈 매장의 천장 화면에 띄우는 전자메뉴판을 만든다. 나는 화면(UI) 담당이다.
화면 장비는 TV가 아니라 안드로이드 보드에 연결한 35~66인치 화면이고, 매장 POS에서 설정한다.
아래에서 "TV"라고 적힌 곳은 모두 이 화면을 뜻한다.
서버, 저장소, 서버 연결, 설치는 다른 담당자가 한다. 그 부분은 만들지 마라.

# 만들 것
A. 메뉴판 화면 네 종류와 번호 띠 (TV용 웹 페이지, 보여 주기만 하고 주문 기능 없음)
B. 수정 화면 일곱 개 (매장 POS의 큰 화면과 폰 화면 모두에서 브라우저로 여는 웹 화면)

# 작업 방식
- 단계마다 화면 설계를 먼저 보여 주고, 내가 확인한 뒤에 코드를 작성한다.
- HTML, CSS, 자바스크립트만 쓴다. 프레임워크와 빌드 도구는 쓰지 않는다.
  다른 담당자가 이 화면을 넘겨받아 서버에 연결하기 때문이다.
- 데이터를 읽고 저장하는 곳은 api.js 한 파일의 함수로만 부른다. 화면 코드에서 서버를 직접 부르지 않는다.
- api.js와 board.js는 다른 담당자가 이미 만들어 실제 서버에 연결해 두었다. 고치지 말고 그대로 쓴다.
  서버 없이 작업해야 할 때만 같은 함수 이름으로 가짜 데이터를 돌려주는 api.js를 따로 만들어 쓴다.
- 계약(데이터 모양, 함수 이름과 인자)을 바꾸고 싶으면 임의로 바꾸지 말고 나에게 제안한다.
  다른 담당자와 합의해야 한다.

# 개발 환경 (함께 받은 POS-server 폴더, 윈도우)
- start-server.bat를 더블클릭하면 서버가 켜진다. 검은 창을 닫으면 꺼진다. 샘플 매장 '우리카페'가 들어 있다.
- 내가 만든 화면 파일은 POS-server\pb_public 폴더에 넣는다. 저장하고 브라우저를 새로 고치면 바로 보인다.
- 메뉴판 화면: http://127.0.0.1:8090/?screen=1&zoom=100 (screen 1 격자, 2 목록, 3 홍보 4K 사진)
  번호 전용 화면과 번호 띠는 수정 화면의 '화면 구성'에서 화면을 더하거나 '번호 띠'를 켜서 본다.
- 수정 화면: http://127.0.0.1:8090/admin.html (로그인 계정은 TEST-ACCOUNTS.txt)
- 수정 화면에서 저장하면 열어 둔 메뉴판 화면이 1초 안에 바뀐다. 두 창을 나란히 두고 확인한다.
- pb_public의 index.html(메뉴판)과 admin.html(수정 화면)은 동작만 확인하는 시안이다.
  함수를 부르는 예시로 읽고, 내 화면으로 통째로 바꾼다. api.js와 board.js는 그대로 둔다.
- 샘플 데이터가 망가지면 서버를 끄고 받은 묶음의 pb_data 폴더로 다시 덮어쓴다.

# 계약 1: 화면이 받는 데이터
```json
{
  "store": { "name": "우리카페", "brandColor": "#c8102e", "backgroundUrl": "https://example.com/bg.jpg" },
  "sections": [ { "id": "s1", "name": "커피", "order": 1 } ],
  "items": [
    { "id": "m1", "sectionId": "s1", "name": "아메리카노",
      "prices": [ { "label": "HOT", "amount": 4500 }, { "label": "ICE", "amount": 5000 } ],
      "photoUrl": "https://example.com/americano.jpg", "order": 1, "soldOut": false, "badge": "new", "posCode": "A01" }
  ],
  "screens": [
    { "no": 1, "type": "grid", "sectionIds": ["s1"], "callBand": true },
    { "no": 2, "type": "list", "sectionIds": ["s2", "s3"], "callBand": false },
    { "no": 3, "type": "promo", "imageUrl": "https://example.com/promo.jpg", "lines": ["첫 줄", "둘째 줄"], "callBand": false },
    { "no": 4, "type": "calls" }
  ],
  "calls": [107, 106, 105]
}
```
- prices는 한 개 또는 두 개. 한 개면 label은 null.
- badge는 "new"(신메뉴), "best"(인기), null 중 하나.
- posCode는 POS 상품 코드(없으면 null). TV 화면에는 보이지 않고, 수정 화면에서 넣고 고친다.
- type은 "grid"(사진 격자형), "list"(목록 + 큰 사진형), "promo"(홍보 화면), "calls"(번호 전용 화면).
- calls는 직원이 부른 번호(1~9999). 가장 최근에 부른 번호가 맨 앞이고, 최대 30개까지 온다.
- callBand가 true인 화면(grid·list·promo)은 아래쪽에 번호 띠를 붙인다. calls 화면에는 callBand가 없다.

# 계약 2: 화면이 부르는 api.js 함수 (모두 Promise를 돌려준다)
- 부르는 방식: 화면에서 <script src="api.js"></script>로 불러오면 전역 객체 api가 생긴다.
  api.getBoard(storeId).then(function (board) { ... }) 처럼 부른다. import/export(모듈)는 쓰지 않는다.
- 실패하면 Promise가 Error로 거절된다. err.message에 사유, err.status에 상태 코드가 있다.
  사유는 아직 서버의 영어 문장이 섞여 온다. 지금은 그대로 보여 주고, 한글로 바꾸는 일은 다른 담당자가 한다.
- 인자와 돌려받는 값의 모양은 getBoard가 돌려주는 모양 그대로다. 수정할 때는 id를 넣고, 새로 만들 때는 id를 뺀다.
- getBoard(storeId) : 메뉴판 전체 (위 데이터 모양). TV 화면과 수정 화면이 같이 쓴다.
  items는 구역 구분 없이 order 순서로 온다. 화면에서 sectionId로 묶는다. 사진이 없으면 photoUrl은 null
- signUp(email, password, storeName) : 개인 매장의 첫 계정 만들기. 만들고 바로 로그인해 login과 같은 값을 돌려준다.
  이미 계정이 있는 서버면 403으로 실패한다(샘플 서버에는 이미 있다).
- login(email, password) : { kind, storeId }를 돌려줌. kind는 hq·franchise·independent 중 하나.
  로그인은 이 기기(브라우저)에 저장되어 아래 저장 함수들이 쓴다.
- session() : 이 기기에 저장된 로그인 { kind, storeId } 또는 null. 수정 화면을 열 때 로그인 화면을 건너뛸지 정한다.
- logout() : 이 기기의 로그인을 지운다.
- saveItem(storeId, item) : 메뉴 추가·수정. 저장한 메뉴의 id를 돌려준다.
  새 사진은 item.photoFile에 파일(input type=file의 File)로 담고, 사진을 지우려면 item.photoUrl을 null로 둔다.
  POS 상품 코드는 item.posCode(지우려면 null, 넘기지 않으면 그대로).
- deleteItem(storeId, itemId) : 메뉴 삭제
- saveSection(storeId, section) : 구역 추가·수정. 저장한 구역의 id를 돌려준다.
- deleteSection(storeId, sectionId) : 구역 삭제. 그 구역의 메뉴도 함께 지워지므로 지우기 전에 묻는다.
- setSoldOut(storeId, itemId, soldOut) : 품절 켜고 끄기
- saveScreens(storeId, screens) : TV 화면 구성 전체 저장. 화면 번호(no)로 맞춰 고치고, 빠진 번호는 지운다.
  홍보 이미지는 screen.imageFile에 파일로 담고, 지우려면 screen.imageUrl을 null로 둔다. 문구는 앞 두 줄만 저장된다.
- saveStore(storeId, store) : 가게 이름, 브랜드 색. 배경 이미지는 store.backgroundFile에 파일로 담고,
  지우려면 store.backgroundUrl을 null로 둔다.
- issuePosKey(storeId) : POS·키오스크 연동 키를 새로 만들어 문자열로 돌려준다. 예전 키는 바로 막힌다.
  키는 이때 한 번만 볼 수 있으니 화면에 띄워 복사하게 하고, 다시 만들기 전에 묻는다.
- 사진 파일은 한 장에 25MB까지 받는다.
- callNumber(storeId, number) : 번호(1~9999)를 부른다. 이미 부른 번호면 맨 앞으로 옮긴다.
  가맹점 계정도 부를 수 있다. 매장마다 최근 30개만 남고 나머지는 서버가 지운다.
- clearCalls(storeId, number) : 부른 번호 하나를 지운다. number를 빼면 그 매장 번호를 모두 지운다.
- listDevices(storeId) : 이 매장에 붙은 TV 목록 [{ id, name, screen }]. screen은 그 TV가 띄운 화면 번호(모르면 null).
  로그인한 매장 계정만 읽을 수 있다. 수정 화면이 "이 화면을 띄운 TV"를 알려 주는 데 쓴다(못 읽으면 일반 문구로).
- listFranchiseStores(), createFranchiseStore(store) : 본사의 가맹점 목록과 등록. 다음 단계라 아직 api.js에 없다.
- onBoardChange(callback) : 메뉴판 화면의 바로 반영용. board.js가 부르므로 화면에서는 부르지 않는다.

# A. 메뉴판 화면
- 매장마다 TV 수와 거는 방향이 다르다. 한 대만 걸 수도, 여러 대를 한 줄로 걸 수도 있고,
  가로로도 세로로도 건다. TV마다 screens의 화면 번호 하나를 띄운다.
- 화면은 안드로이드 보드(RK3568, 안드로이드 11~14)의 내장 브라우저(WebView)가 그린다.
  안드로이드 11 이상이라 flex, CSS Grid, CSS 변수 같은 요즘 기능을 쓸 수 있다.
- 화면 크기는 35인치부터 66인치까지이고, 해상도는 1920×1080부터 4K(3840×2160)까지다. 세로로 걸면 1080×1920처럼 온다.
  크기를 px로 고정하지 말고 화면의 긴 변에 비례하게(vmax, rem) 잡아 어느 해상도와 방향에서도 같은 크기로 보이게 한다.
  가로·세로 배치는 @media (orientation: portrait)로 나눈다(세로면 구역을 옆이 아니라 아래로 쌓는 식).
  사진은 4K에서도 흐려지지 않게 원본을 그대로 쓰고 object-fit으로 맞춘다.
- 글자 크기에는 CSS 변수 --zoom(기본 1)을 곱한다. 예: html{font-size:calc(1.5vmax * var(--zoom, 1))}.
  설치자가 화면 크기에 맞춰 보드마다 배율을 조절하면 board.js가 이 변수를 넣어 준다.
- 화면 종류는 정해진 네 가지뿐이다.
  - 사진 격자형: 화면당 메뉴 6~8개, 사진·이름·가격. 사진 없는 메뉴는 넣지 않는다.
  - 목록 + 큰 사진형: 목록 최대 10줄, 큰 사진 2~3장.
  - 홍보 화면: 이미지 한 장, 문구 최대 두 줄.
  - 번호 전용 화면: TV가 여러 대인 매장에서 한 대를 번호 호출용으로 쓴다. 가장 최근 번호를 아주 크게,
    그 앞 번호 몇 개를 작게. 번호가 없으면 빈 화면 대신 매장 이름과 안내를 둔다.
- 번호 띠: TV가 한 대뿐인 매장용. callBand가 켜진 메뉴·홍보 화면의 아래쪽에 최근 번호 몇 개를 한 줄로 붙인다.
  가장 최근 번호를 강조색으로. 띠가 붙어도 메뉴가 잘리지 않게 메뉴 쪽이 줄어든다.
- 번호가 새로 불리면 renderBoard가 다시 불린다(1초 안). 다른 이유(가격 수정)로 다시 불릴 때도 있으니,
  새 번호를 깜빡이게 하려면 이전에 그린 첫 번호와 다를 때만 깜빡인다.
- 모든 화면에 매장 배경 이미지와 브랜드 색을 깔고, 메뉴 화면은 띠 모양 제목으로 구역을 나눈다.
- 가격은 한 개 또는 두 개(HOT/ICE 같은 이름표), 신메뉴·인기 딱지, 품절은 흐리게 표시한다.
- 스크롤과 마우스 커서가 없다. 1920×1080, 3840×2160, 세로 1080×1920에서 모두
  잘림 없이 확인한다(브라우저 개발자 도구의 기기 크기 설정). zoom=150에서도 글이 잘리지 않아야 한다.
- 세로 flex 안에 사진과 글을 같이 둘 때는 사진에 flex:1; min-height:0; object-fit:contain을 준다.
  사진 높이를 vh로 고정하면 4K에서 글 줄이 화면 밖으로 밀려난다(시안에서 실제로 겪은 문제).
- 5분마다 다시 읽기와 연결이 끊겼을 때의 처리는 다른 담당자가 만든 board.js가 한다.
  메뉴판 화면(index.html)은 전역 함수 renderBoard(board, screenNo) 하나만 정의하면 된다.
  board는 계약 1의 데이터, screenNo는 이 TV가 띄울 화면 번호(숫자)다. 같은 함수가 여러 번
  불리므로, 불릴 때마다 화면을 비우고 처음부터 다시 그린다.
- index.html 맨 아래에는 화면 스크립트 다음에 <script src="api.js"></script>,
  <script src="board.js"></script>를 이 순서로 둔다. 화면에서 getBoard를 직접 부르지 않는다.
- 보드는 /?screen=화면번호&zoom=배율 주소로 연다. 주소 읽기도 board.js가 한다.
- 메뉴 이름처럼 사람이 입력한 글은 innerHTML이 아니라 textContent로 넣는다.

# B. 수정 화면 일곱 개
1. 로그인 (개인 매장은 처음 한 번 이메일과 비밀번호로 계정을 만듦)
2. 홈 (계정 종류에 따라 보이는 것이 다름)
3. 메뉴 관리 (이름, 가격, 구역, 사진, 표시 순서, 품절, 딱지)
4. 화면 구성 (TV마다 화면 종류와 표시할 구역, 번호 띠 켜고 끄기 고르기)
5. 홍보 화면 (이미지와 문구)
6. 미리보기 후 저장
7. 번호 호출 (영업 중 가장 자주 쓰는 화면. 큰 숫자 버튼으로 번호를 넣고 호출,
   부른 번호를 눌러 하나씩 지우기, 전체 지우기. 홈에서 한 번에 들어갈 수 있게 둔다.
   가맹점 계정도 이 화면은 쓴다)

계정 종류: 이번에는 매장 계정 하나만 만든다. login이 돌려주는 kind가 "independent"인 계정이고,
자기 매장의 전부를 고칠 수 있다. 본사(hq)와 가맹점(franchise) 화면은 다음 단계라 만들지 않는다.
다만 홈 화면은 kind에 따라 메뉴를 다르게 보여 줄 수 있는 구조로 둔다.
POS의 큰 가로 화면(터치)과 폰의 좁은 화면 모두에서 쓸 수 있어야 한다.
