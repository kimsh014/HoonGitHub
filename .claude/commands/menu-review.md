메뉴판 검토단을 돌린다. 인자: $ARGUMENTS

# 검토단 구성 (분야마다 3명)

| 분야 | 검토자 |
|---|---|
| 계약 (계약·회귀) | `menu-contract-api`, `menu-contract-tests`, `menu-contract-migration` |
| 보안 | `menu-sec-access`, `menu-sec-keys`, `menu-sec-web` |
| 설치 (하드웨어·설치·업데이트) | `menu-hw-test`, `menu-install-check`, `menu-update-check` |
| 화면 | `menu-ui-board-check`, `menu-ui-admin-check`, `menu-ui-spec-check` |

# 순서

1. **대상 정하기.** 인자의 첫 단어로 분야를 고른다(없거나 "전체"면 네 분야 모두). 기준 브랜치나 PR 번호가 있으면 그 변경을, 없으면 저장소 기본 브랜치 대비 현재 브랜치의 변경을 검토 대상으로 한다. 바뀐 파일 목록(`git diff --stat`)을 만든다.
2. **1차 검토 (병렬).** 고른 분야의 검토자 전원을 한 메시지에서 동시에 Agent로 부른다. 각 검토자에게 대상(브랜치, 바뀐 파일 목록)과 "자기 역할 범위만 보고, 보고 형식대로 답하라"를 넘긴다. 내 생각이나 예상 결론은 넘기지 않는다.
3. **지적 모으기.** 같은 `파일:줄`과 같은 원인을 가리키는 지적은 하나로 합치고, 몇 명이 독립적으로 찾았는지 센다.
4. **교차 확인 (병렬).** 한 명만 찾은 높음·중간 지적은, 같은 분야에서 그 지적을 하지 않은 검토자 한 명에게 지적 내용만 넘겨 "사실인지 직접 확인하고 확인됨/아님/판단 불가와 근거를 답하라"고 맡긴다. 지적끼리 독립적이면 동시에 부른다. 두 명 이상이 독립적으로 찾은 지적은 교차 확인 없이 확인된 것으로 본다.
5. **판정.**
   - 확정: 두 명 이상이 찾았거나, 교차 확인에서 "확인됨".
   - 보류: 교차 확인이 "판단 불가"(무엇이 있으면 판정되는지 적는다).
   - 기각: 교차 확인이 "아님"(근거 한 줄과 함께 보고 맨 끝에 남긴다).
   - 낮음 지적은 교차 확인 없이 "참고"로 둔다.
6. **보고.** 사용자에게 한국어로:
   - 맨 위 한 줄: 분야별 확정 개수(높음/중간), 보류 개수.
   - 확정 지적 표: 심각도, 분야, `파일:줄`, 내용, 찾은 검토자 수(예: 3명 중 2명), 고치는 방향.
   - 보류·참고·기각 목록.
   - 돌리지 못한 검사(예: Windows 전용 단계, 실제 하드웨어)와 사람이 직접 해야 할 일.

# 규칙
- 검토자는 코드를 고치지 않는다. 이 명령도 고치지 않는다. 고칠지는 보고를 본 사용자가 정한다.
- 검토자가 실패하거나 빈 답을 내면 한 번 다시 부르고, 또 실패하면 그 검토자를 "실패"로 보고에 적는다. 2명 이하로 끝난 분야는 그렇다고 분명히 적는다.
- 비밀 정보 값은 보고에 옮기지 않는다.
